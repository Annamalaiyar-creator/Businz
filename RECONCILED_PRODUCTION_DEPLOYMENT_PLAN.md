## 2. Investigation of Untracked 5.8 GB Core Dump & Backup Files

During the inspection of the live `/var/www/businz` directory on Hostinger VPS, four untracked files were identified:
1. One **5.8 GB Linux core dump file** (`core` or `core.<pid>`).
2. Three **backup archive files** (`.bak` or `*.json.bak`).

### Technical Analysis & Origins
- **5.8 GB Core Dump:**
  - **Origin:** Generated by the Linux operating system kernel when a Node.js process previously terminated abruptly (e.g. out-of-memory SIGABRT or fatal allocation error prior to our Phase 1–4 memory and stream optimizations).
  - **Impact:** Consumes 5.8 GB on the root filesystem, but has zero runtime impact on active Node.js / PM2 services.
- **Three Backup Files:**
  - **Origin:** Preserved copies of configuration or store files from earlier manual maintenance.

### Strict Safety & Preservation Rules
- **Rule 1 (Do Not Delete/Modify):** In strict compliance with instructions, the deployment script **NEVER** deletes, moves, or alters the 5.8 GB core dump or the three `.bak` files.
- **Rule 2 (Cleanliness Check Separation):** The working tree inspection strictly distinguishes tracked modifications from untracked files:
  ```bash
  TRACKED_DIRTY=$(git status --porcelain | grep -v '^\?\?' || true)
  ```
  Only uncommitted changes to tracked code files will trigger a safety halt. Untracked artifacts are logged and preserved.
- **Rule 3 (Exclusion from Backup Tarballs):** All backup and tar operations explicitly exclude `core*` and large `.bak` files:
  ```bash
  tar --exclude='core*' --exclude='*.bak' -czf ...
  ```
  This prevents copying 5.8 GB of dead core dump data into `/var/backups/businz`, preventing disk exhaustion and keeping backup duration under 30 seconds.
